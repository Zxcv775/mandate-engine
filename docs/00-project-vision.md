# 00 · 项目愿景

> 项目暂定名称：**天命：帝国推演**（Mandate Engine）。
> 名称未来可修改，内部架构不与名称耦合（代码内仅使用 `@mandate/*` 包作用域代号）。

## 1. 项目定位

一款由大语言模型（LLM）驱动的**中国历史政治模拟游戏**。玩家扮演某一历史时期的皇帝，
通过阅读奏报、召开会议、任免官员、制定政策、处理战争、财政、灾害、党争、民变与宫廷事务，
影响国家的走向。

核心原则：

> **LLM 负责扮演人物、生成语言和解释结果；规则引擎负责计算国家状态、政策后果和历史约束。**

游戏不完全依赖 LLM 自由发挥。国库数字、人口变化、战斗结果、灾害损失、政策最终效果等
一切重要状态变化，必须经过可测试、可复现的规则系统计算。

## 2. 玩家幻想

"朕即国家。"

- 坐在御案后，面对的不是菜单和按钮，而是雪片般的奏折、各怀心思的臣子和一个真实的帝国；
- 可以用自己的话颁布任何政策——但政策要经过制度的过滤、官僚的执行和现实的检验；
- 每个臣子都是独立的人：有人格、有派系、有私心、有认知局限，会欺瞒、会结党、会阳奉阴违；
- 皇帝不是全知的：你看到的只是呈到你面前的信息，而信息可能迟到、失真或被刻意隐瞒。

## 3. 核心玩法

1. **批阅奏报**：阅读来自六部、都察院、厂卫、地方督抚的奏折与情报，分辨真伪；
2. **召开会议**：朝会（公开表态）、御前会议（决策协调）、秘密议事（情报与阴谋）三种规则环境；
3. **人事任免**：任免内阁、六部、督抚、将领，平衡派系与能力；
4. **制定政策**：用自然语言提出政策，系统生成草案、廷议、裁决、结算；
5. **推进时间**：观察政策效果、灾害、战争、民变与历史事件的展开；
6. **经营信息**：建设信息渠道（厂卫、言官、密折），对抗信息失真。

## 4. 核心循环

```text
时间推进
  → 规则引擎结算（财政/粮食/军队/灾害/事件触发）
  → 生成奏报与情报（LLM 基于规则结果撰写文本）
  → 玩家阅读、召开会议、与臣子对话（LLM 角色扮演）
  → 玩家形成决策（自然语言）
  → 政策草案 → 制度约束检查 → 廷议意见 → 玩家最终裁决
  → 规则引擎计算后果 → 更新唯一可信状态 + 写入变更日志
  → 叙事生成（LLM）→ 记忆写入
  → 进入下一回合
```

注意：**规则计算永远先于叙事生成**，不允许先写故事再反推数值。

## 5. 目标用户

- 中国历史爱好者（尤其是晚明史爱好者）；
- 策略/模拟游戏玩家（P 社游戏、《皇帝成长计划》类玩家）；
- AI 叙事/角色扮演游戏爱好者（期待比"角色卡聊天"更有深度的系统）；
- 对"LLM + 规则引擎"混合架构感兴趣的开发者。

## 6. 与普通策略游戏的区别

| 维度     | 普通策略游戏         | 本项目                         |
| -------- | -------------------- | ------------------------------ |
| 交互方式 | 菜单、按钮、固定选项 | 自然语言决策 + 固定系统操作    |
| 人物     | 数值化的将领/顾问    | 有人格、记忆、派系和私心的角色 |
| 信息     | 玩家近似全知         | 信息不完整、可失真、可欺瞒     |
| 政策     | 预设政策卡           | 玩家自由表述，系统解析与结算   |
| 叙事     | 事件弹窗             | 由规则结果驱动的连续叙事       |

## 7. 与纯聊天角色卡的区别

| 维度     | 纯聊天角色卡 | 本项目                           |
| -------- | ------------ | -------------------------------- |
| 事实来源 | LLM 即兴发挥 | 规则引擎 + 唯一可信状态          |
| 数值     | 无或装饰性   | 国库/人口/军队等经确定性计算     |
| 可复现性 | 不可复现     | 固定种子可复现判定序列           |
| 历史约束 | 靠提示词约束 | 历史模板数据 + 制度包 + 条件事件 |
| 失败可能 | 几乎没有     | 财政崩溃、民变、亡国真实存在     |

## 8. 设计原则

1. **规则优先，叙事后置**：先计算，后写作；禁止文本反推数值；
2. **单一事实源（Single Source of Truth）**：所有模块读取统一 GameState，任何修改留痕（StateChangeLog）；
3. **历史模板与运行状态分离**：模板只读、带来源标注；运行状态可修改、可存档；
4. **数据驱动**：朝代差异通过"制度包"数据表达，规则以 Modifier + 条件 DSL 表达，不堆 if-else；
5. **LLM 输出不可信**：一律经 Schema 校验，LLM 不得直接写状态、执行代码或访问文件；
6. **可测试**：核心计算脱离 LLM 可运行；随机系统支持固定种子；
7. **信息不完全**：玩家与 NPC 都只能看到自己权限内的信息；
8. **历史诚实**：史实、争议、推测、可玩性调整四类标注，不伪造确定结论。

## 9. 明确不做的内容

- 不做实时多人游戏；
- 不做 3D 画面、不做语音；
- 不做付费系统、不做云端部署（本地单机优先）；
- 不做手机原生客户端；
- 不引入微服务架构与重基础设施（向量数据库等）；
- 不把网络传说、文学演义默认视为史实；
- 不让 LLM 直接决定数值结果。

## 10. 长期发展方向

1. **多朝代制度包**：秦汉、隋唐、两宋、元、清、架空朝代，通过数据包扩展而非改核心代码；
2. **创作者工具**：剧本/人物/事件的数据编辑与校验工具，支持社区创作；
3. **桌面化**：网页版稳定后可用 Tauri 打包为桌面应用；
4. **更精细的模拟**：在保持可测试的前提下逐步加深财政、军事、人口模型；
5. **AI 可解释性**：让玩家能追问"为什么会这样"，并看到规则链条与史实测注。
