# ADR-002 · LLM 与规则引擎的责任边界

- 状态：**已接受**
- 日期：2026-07-26

## 背景

LLM 具有幻觉与不可预测性。若允许 LLM 直接决定国库、人口、战斗、灾害等数值，
游戏将不可测试、不可复现、不可平衡，且玩家会失去对"因果关系"的信任。
项目核心原则要求：LLM 负责语言与人格，规则引擎负责数值与后果。

## 决策

1. **规则优先，叙事后置**：固定流程为
   玩家下令 → 意图解析 → 政策草案 → 制度约束检查 → NPC 意见 → 玩家裁决
   → 规则引擎计算 → 状态更新 → 叙事生成 → 日志与记忆。
   禁止先由 LLM 编写结果再反向修改数值。
2. **LLM 输出一律视为不可信输入**：一切结构化输出经 Zod Schema 校验；
   失败按配置重试，仍失败则抛出 StructuredOutputError 并由应用层降级。
3. **Agent 层无状态写入口**：LLM 只能产出文本、草案、摘要（白名单见领域模型文档第 3 节），
   由系统决定如何落入状态。
4. **LLM 视图按角色过滤**：隐藏状态与越权信息不进入 Prompt。
5. LLM 不得执行代码、访问文件、直接写库；Prompt 文本不作为系统指令执行。

## 选择理由

- 可测试性：核心计算脱离 LLM 运行（FR-TEST-001）；
- 可复现性：种子随机 + 确定性结算；
- 安全性：隔离不可信输出；
- 可平衡性：数值只来自数据驱动的规则。

## 替代方案

- LLM 全权叙事引擎（"AI 地牢"式）：不可测试、数值崩坏，拒绝；
- LLM 提数值、规则只做范围校验：仍有幻觉空间，拒绝；
- 完全无 LLM：失去项目核心体验，拒绝。

## 后果

- 正面：架构清晰、可测试、可复现、安全；
- 负面：需要维护"草案→校验→结算"的双层管道，工程量大于纯聊天；
- 叙事质量依赖"规则结果→叙事"的 Prompt 工程质量。

## 风险

- LLM 结构化输出不稳定 → 重试 + 降级 + Mock 测试兜底；
- 开发者图省事绕过边界 → 依赖方向静态检查 + 评审把关。
