# ADR-001 · 架构风格：模块化单体 + 前后端分离

- 状态：**已接受**
- 日期：2026-07-26

## 背景

本项目为单机单人游戏，由单人/小团队开发。系统包含表现层、应用服务、Agent 编排、
状态/规则/事件引擎、数据访问等多个关注点，需要清晰的模块边界；
但过早拆分服务会带来部署、调试、事务一致性的巨大成本。

## 决策

采用**模块化单体**：

- 单一服务端进程（`apps/server`）承载应用服务、Agent 编排与全部引擎；
- 内部以 npm workspaces 的 `packages/*` 划分模块，用依赖规则强制边界
  （如引擎禁止依赖 llm-adapters；状态写入只有一个入口）；
- 前端为独立 SPA（`apps/web`），经 HTTP/SSE 与后端通信。

## 选择理由

- 单机游戏无需水平扩展；
- 单进程内调用引擎，避免网络序列化成本与分布式一致性难题；
- packages 划分保留未来拆分的可能（引擎可独立测试、可整体拆出）。

## 替代方案

- 微服务：运维与调试成本远超收益，拒绝；
- 前后端同体（服务端渲染）：不利于桌面化与 UI 迭代，拒绝；
- 全前端（无后端）：LLM Key 无法保密、存档/日志能力弱，拒绝。

## 后果

- 正面：开发简单、测试容易、一处部署；
- 负面：模块边界依赖纪律维护（lint 规则 + 代码评审），单体随规模变大需持续治理。

## 风险

- 模块边界腐化 → 以依赖方向规则（架构文档第 3 节）与静态检查约束；
- 未来若需云服务/多人，需要拆分 → packages 边界即为拆分线。
