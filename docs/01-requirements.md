# 01 · 需求规格

本文档使用可测试的方式描述需求。每条需求包含：ID、描述、优先级、验收标准。

## 1. 优先级定义

| 优先级 | 含义 |
|---|---|
| P0 | MVP 必须完成（见第 3 节 MVP 范围冻结） |
| P1 | 正式版本需要 |
| P2 | 后续增强 |
| P3 | 远期设想 |

## 2. 需求总览

### 2.1 状态引擎（STATE）

| ID | 描述 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-STATE-001 | 系统维护唯一可信 GameState：当前日期、回合数、国家、地区、人物状态、官职任职、派系、关系、政策、进行中的会议、军队、战争、已触发事件、隐藏状态 | P0 | 单元测试：构造 GameState 对象通过 Schema 校验；字段齐全 |
| FR-STATE-002 | 所有状态修改必须产生 StateChangeLog（含修改路径、before/after、操作者、规则引用、游戏日期） | P0 | 任意状态变更后日志条数 +1 且必填字段非空 |
| FR-STATE-003 | 隐藏状态（真实忠诚、阴谋值、情报准确度）对玩家及无权限 NPC 不可见 | P0 | 提供给 LLM 的状态视图经测试不含 hidden 字段 |
| FR-STATE-004 | 状态写入只有一个入口（状态引擎），Agent、UI、叙事模块不得直接改状态 | P0 | 代码走查 + 模块依赖静态检查 |

### 2.2 会议系统（MEET）

| ID | 描述 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-MEET-001 | 支持朝会、御前会议、秘密议事三种类型，各自拥有独立规则参数（人数上限、公开性、是否产生正式记录、泄密基准概率、合法性修正、坦率基准、政治风险基准） | P0 | 三类规则对象通过 Schema 校验且参数互不相同 |
| FR-MEET-002 | 会议参与人数受该类型规则上限约束 | P0 | 超限加入被拒绝并返回结构化原因 |
| FR-MEET-003 | 秘密议事按基准概率（可受人物忠诚、厂卫能力修正）产生泄密事件 | P0 | 固定种子下泄密判定序列可复现 |
| FR-MEET-004 | 朝会发言写入正式会议记录（Memory，kind=meeting_record）；秘密议事默认不产生公开记录 | P0 | 会议结束后按类型断言记录存在/不存在 |
| FR-MEET-005 | 会议类型影响 NPC 发言意愿与真实性（坦率基准参与发言生成约束） | P0 | Prompt 组装测试：会议规则参数进入 NPC 上下文 |
| FR-MEET-006 | 会议中形成的政策获得对应类型的合法性修正 | P0 | 政策对象 legitimacyModifier 与会议类型一致 |
| FR-MEET-101 | 会议发言影响派系态度与人物关系数值（由规则引擎结算，不由 LLM 直接赋值） | P1 | 规则结算单元测试 |
| FR-MEET-102 | 会议可被厂卫监听并生成情报报告 | P2 | 条件触发测试 |

### 2.3 人物系统（CHAR）

| ID | 描述 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-CHAR-001 | 人物模板包含：姓名、字号、生卒年、人格特质、四维能力（政务/军事/权谋/学识）、野心、私人目标、知识范围、派系、史料来源标注 | P0 | Schema 校验通过；sourceIds 非空 |
| FR-CHAR-002 | NPC 发言只能基于其知识范围内的信息（信息不完全） | P0 | Prompt 组装测试：越权信息不出现在该 NPC 上下文 |
| FR-CHAR-003 | NPC 忠诚/态度变化由规则引擎根据政策、事件、赏罚计算 | P0 | 固定输入下态度变化值等于规则计算值 |
| FR-CHAR-004 | NPC 可基于忠诚度与情境选择欺瞒（奏折/发言附带 truthfulness 隐藏值） | P0 | 生成管道测试：truthfulness 字段存在且不暴露给玩家视图 |
| FR-CHAR-101 | NPC 拥有跨回合记忆（摘要式长期记忆） | P1 | 记忆写入/读取测试 |

### 2.4 政策与规则（POL / RULE）

| ID | 描述 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-POL-001 | 玩家自然语言指令经 Policy Parser 转为结构化政策草案（JSON，经 Zod 校验） | P0 | Mock LLM：合法草案被接受，非法草案被拒绝并重试 |
| FR-POL-002 | 草案须通过权限与制度约束检查（制度包定义）后方可颁布 | P0 | 越权草案被拒绝并返回违制原因文本 |
| FR-POL-003 | 颁布政策由规则引擎计算 Modifier 列表并更新状态；LLM 不得直接给出数值结果 | P0 | 固定输入两次计算结果完全一致（确定性） |
| FR-POL-004 | 政策执行受地方控制度、官僚效率、腐败影响，产生执行偏差 | P0 | 高阻力地区的执行效果低于基准（数值断言） |
| FR-RULE-001 | 全部随机判定使用可固定种子的 RNG | P0 | 同种子两次运行判定序列逐项相等 |
| FR-RULE-002 | 规则以数据驱动：Modifier + 白名单条件表达式 DSL；禁止 eval / new Function | P0 | 代码扫描无动态执行；恶意表达式被拒绝 |
| FR-RULE-003 | 规则可叠加：政策、人物、制度、地区修正按定义顺序合成 | P1 | 合成顺序单元测试 |

### 2.5 事件与时间（EVT）

| ID | 描述 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-EVT-001 | 时间以回合推进；每回合结算顺序固定：到期 Modifier → 财政/粮食 → 事件条件检测 → 状态衰减 → 风险累积 | P0 | 推进 N 回合后日期与结算调用顺序符合规格 |
| FR-EVT-002 | 条件事件仅在表达式满足时触发；默认每个事件只触发一次（可标记可重复） | P0 | 触发/不触发/不重复三分支测试 |
| FR-EVT-003 | 固定历史事件按剧本日期触发，但玩家行为可通过前置条件改变其结果分支 | P0 | 不同前置状态产生不同分支（测试） |
| FR-EVT-101 | 连锁事件按 EventChain 定义推进 | P1 | 链式推进测试 |

## 3. MVP 范围冻结

### MVP 包含

- 单一剧本：崇祯初政（初始时间：崇祯即位初期）；
- 单一朝代制度包：明朝；
- 约 8–12 名核心人物；
- 三种会议：朝会、御前会议、秘密议事；
- 奏折阅读；
- 自然语言皇帝指令 → 政策草案 → 廷议 → 裁决 → 规则结算；
- 简化财政 / 军队 / 民生 / 派系模型；
- 人物态度与忠诚；
- 时间推进与条件事件；
- 自动存档（SQLite）；
- 一个 LLM 供应商（OpenAI 兼容接口）+ 一个 Mock 供应商；
- 基础调试面板。

### MVP 不包含

- 全国精细地图；
- 复杂即时战争模拟；
- 多朝代；
- 多人模式；
- 语音、3D 画面；
- 手机原生客户端；
- 玩家自制模组编辑器；
- 向量数据库与复杂多 Agent 服务。
